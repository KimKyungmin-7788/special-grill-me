# 개발 인계 세트 템플릿

개발 인계 세트를 만들 때 읽는다. 작성 규칙과 폴더 구성은 SKILL.md의 '개발 인계 세트'에 있다.

## 목차

1. 표기 방법
2. AGENTS.md
3. CLAUDE.md
4. DEVELOPMENT.md
5. DESIGN.md
6. AGENTS-add.md (기존 프로젝트)
7. 인계 세트의 PRD
8. 시작 프롬프트

## 1. 표기 방법

- `<...>`는 인터뷰 결과로 채우는 자리다. 채울 내용이 없으면 그 줄이나 섹션을 지운다.
- `<...>`가 없는 문장은 고정 문구이므로 그대로 둔다.
- `(세팅 후 에이전트가 채움)`은 그대로 남긴다. 개발 도구가 프로젝트를 세팅한 뒤 실제 값으로 바꾼다.
- 문서는 인터뷰를 진행한 언어로 쓴다.

## 2. AGENTS.md

새 프로젝트일 때만 만든다. 60줄 안팎을 넘기지 않는다.

```markdown
# <프로젝트명>

<한 줄 요약>

## 문서
- docs/PRD.md: 무엇을, 왜 만드는가
- docs/DEVELOPMENT.md: 어떤 순서로, 어떻게 만드는가
- docs/DESIGN.md: 화면과 디자인 규칙

작업을 시작하기 전에 관련 문서를 읽는다. 문서와 코드가 어긋나면 고치기 전에 먼저 알린다.

## 기술 스택
- <정해진 기술 이름>

## 실행 명령어
(세팅 후 에이전트가 채움)

## 폴더 구조
(세팅 후 에이전트가 채움)

## 작업 규칙
- <인터뷰에서 정한 일하는 방식>
- 문서에 없는 결정이 필요하면 임의로 정하지 않고 사용자에게 묻는다.
- 한 단계를 마치면 docs/DEVELOPMENT.md의 완료 확인 방법대로 점검하고 결과를 알린다.
- 결정이 바뀌면 해당 문서도 함께 고친다.

## 하지 말 것
- <인터뷰에서 정한 금지 사항>
```

DESIGN.md를 만들지 않았으면 '문서' 목록에서 그 줄을 뺀다.

## 3. CLAUDE.md

새 프로젝트일 때만 만든다. 기본은 아래 한 줄이 전부다.

```markdown
@AGENTS.md
```

클로드 코드에만 해당하는 규칙이 인터뷰에서 나왔을 때만 아래처럼 덧붙인다.

```markdown
@AGENTS.md

## 클로드 코드 전용
- <클로드 코드에만 해당하는 규칙>
```

## 4. DEVELOPMENT.md

```markdown
# <프로젝트명> 개발 문서

기술 스택은 AGENTS.md에, 만드는 이유와 범위는 PRD.md에 있다.

## 1. 배포와 운영
- 배포 위치: <...>
- 로그인: <...>
- 보안과 개인정보: <...>

## 2. 데이터
- 저장하는 것: <...>
- 저장 위치: <...>
- 저장하지 않는 것: <...>

## 3. 개발 단계

### 1단계: <이름>
- 만드는 것: <...>
- 완료 확인 방법: <무엇을 보면 끝났다고 판단하는가>

### 2단계: <이름>
- 만드는 것: <...>
- 완료 확인 방법: <...>

## 4. 일정
- <정해진 기한>
```

기존 프로젝트에 추가하는 경우 첫 줄 안내를 "기존 기술 스택을 따른다. 만드는 이유와 범위는 PRD.md에 있다."로 바꾸고, 기존과 달라지는 것만 적는다.

## 5. DESIGN.md

화면이 있는 프로젝트일 때만 만든다.

```markdown
# <프로젝트명> 디자인 문서

사용자와 사용 맥락은 PRD.md 3장에 있다. 이 문서는 거기서 나온 화면 규칙을 적는다.

## 1. 화면 규칙
- 글자와 버튼 크기: <...>
- 한 화면의 정보량: <...>
- 문장 수준과 말투: <...>
- 접근성: <...>

## 2. 분위기와 스타일
- 색: <...>
- 글꼴: <...>
- 전체 인상: <...>

## 3. 화면 목록
| 화면 | 목적 | 주요 요소 |
|---|---|---|
| <...> | <...> | <...> |

## 4. 공통 요소
- 버튼과 입력: <...>
- 피드백(성공, 실패, 완료 표시): <...>
- 소리와 움직임: <...>
```

## 6. AGENTS-add.md (기존 프로젝트)

기존 프로젝트에 추가할 때 AGENTS.md와 CLAUDE.md 대신 만든다.

```markdown
# <기능명> 작업 지침

기존 지침 파일(AGENTS.md 또는 CLAUDE.md)에 합칠 내용이다. 합친 뒤 이 파일은 지워도 된다.

## 문서
- handoff-<slug>/PRD.md: 무엇을, 왜 만드는가
- handoff-<slug>/DEVELOPMENT.md: 어떤 순서로, 어떻게 만드는가
- handoff-<slug>/DESIGN.md: 화면과 디자인 규칙

## 이 기능의 작업 규칙
- <인터뷰에서 정한 일하는 방식>
- 문서에 없는 결정이 필요하면 임의로 정하지 않고 사용자에게 묻는다.
- 한 단계를 마치면 DEVELOPMENT.md의 완료 확인 방법대로 점검하고 결과를 알린다.

## 하지 말 것
- <인터뷰에서 정한 금지 사항>
```

## 7. 인계 세트의 PRD

SKILL.md의 PRD 템플릿을 쓰되 두 섹션을 뺀다. 같은 내용을 두 곳에 적지 않기 위해서다.

- '기술·운영 조건' 섹션을 빼고, 그 자리에 "기술과 운영 조건은 DEVELOPMENT.md에 있다." 한 줄을 둔다.
- '일정' 섹션을 뺀다. 개발 단계와 일정은 DEVELOPMENT.md에 적는다.

## 8. 시작 프롬프트

파일로 만들지 않는다. 마지막 답변에 코드박스 하나로, 마크다운 서식 없이 일반 텍스트로 제시한다. 클로드 코드와 코덱스에 같은 글을 쓴다. 만들지 않은 문서는 목록에서 뺀다.

새 프로젝트:

```text
이 폴더는 <프로젝트명> 프로젝트입니다. 코드를 쓰기 전에 아래 순서대로 진행해 주세요.

1. AGENTS.md와 docs 폴더의 PRD.md, DEVELOPMENT.md, DESIGN.md를 모두 읽습니다.
2. 이해한 내용을 다섯 줄 이내로 요약하고, 문서끼리 어긋나거나 빠진 부분이 있으면 질문합니다.
3. DEVELOPMENT.md의 1단계를 어떻게 진행할지 계획을 보여 주고 제 승인을 기다립니다.
4. 승인을 받으면 1단계만 진행하고, 문서에 적힌 완료 확인 방법대로 점검한 결과를 알려 줍니다.
5. 프로젝트 세팅이 끝나면 AGENTS.md의 "세팅 후 에이전트가 채움" 칸을 실제 값으로 채웁니다.

문서에 없는 결정이 필요하면 임의로 정하지 말고 먼저 물어봐 주세요.
```

기존 프로젝트에 추가:

```text
이 프로젝트에 <기능명> 기능을 추가하려고 합니다. 코드를 쓰기 전에 아래 순서대로 진행해 주세요.

1. handoff-<slug> 폴더의 PRD.md, DEVELOPMENT.md, DESIGN.md, AGENTS-add.md를 모두 읽습니다.
2. 현재 코드와 기존 지침 파일(AGENTS.md 또는 CLAUDE.md)을 살펴보고, 문서 내용이 실제 코드와 다른 부분을 먼저 알려 줍니다.
3. AGENTS-add.md의 내용을 기존 지침 파일에 합칩니다. 기존 규칙은 지우지 말고, 서로 충돌하는 규칙이 있으면 합치기 전에 저에게 묻습니다.
4. DEVELOPMENT.md의 1단계를 어떻게 진행할지 계획을 보여 주고 제 승인을 기다립니다.
5. 승인을 받으면 1단계만 진행하고, 문서에 적힌 완료 확인 방법대로 점검한 결과를 알려 줍니다.

문서에 없는 결정이 필요하면 임의로 정하지 말고 먼저 물어봐 주세요.
```
